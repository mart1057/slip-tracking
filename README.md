# สมุดสลิป (Slip Tracker)

ส่งรูปสลิปโอนเงินเข้า Telegram แล้วระบบจะบันทึกลง Postgres ตอบสรุปยอดของธนาคารที่รับเงิน
และมี dashboard ดูยอดรับโอนแยกธนาคารเทียบเกณฑ์ที่ธนาคารต้องส่งข้อมูลให้กรมสรรพากร

คำสั่งที่ใช้บ่อยทั้งหมด (หยุด เริ่ม ดู log อัปเดต สำรองข้อมูล) อยู่ใน [COMMANDS.md](COMMANDS.md)

```
slip-tracker/
  COMMANDS.md        คำสั่งที่ใช้บ่อย
  db/schema.sql      ตาราง accounts และ slips
  bot/               Telegram bot + API (Node.js)
  dashboard/         หน้า dashboard (Next.js)
```

## ติดตั้งครั้งแรก

ต้องมี Node.js 20 ขึ้นไป และ Postgres ที่รันอยู่ในเครื่อง

1. สร้าง bot: คุยกับ @BotFather ใน Telegram ส่ง `/newbot` แล้วเก็บ token ที่ได้
2. ตั้งค่าและสร้างฐานข้อมูล
   ```bash
   cd bot
   npm install
   cp .env.example .env        # ใส่ TELEGRAM_BOT_TOKEN
   npm run db:init             # สร้างฐานข้อมูล slip_tracker และตาราง
   npm start
   ```
3. เปิด Telegram ส่ง `/id` ให้ bot แล้วนำเลขที่ได้ไปใส่ `ALLOWED_TELEGRAM_USER_IDS` ใน `bot/.env`
   จากนั้นหยุด (Ctrl+C) แล้ว `npm start` ใหม่
4. ตั้งบัญชีรับเงินของคุณ เพื่อให้ระบบรู้ว่าสลิปแต่ละใบเข้าธนาคารไหน
   ```
   /addaccount กสิกร 123-4-56789-0 0812345678
   /addaccount scb 987-6-54321-0
   ```
   เลขตัวที่สามเป็นต้นไปคือเบอร์โทรหรือเลขบัตรที่ผูกพร้อมเพย์กับบัญชีนั้น (ไม่มีก็ไม่ต้องใส่)
5. เปิด dashboard (อีกหน้าต่าง Terminal)
   ```bash
   cd dashboard
   npm install
   npm run build
   npm start                   # http://localhost:3210
   ```
   เครื่องอื่นในวงแลนเดียวกันเปิดได้ที่ `http://<IP ของ Mac mini>:3210`
   ถ้าต้องการให้ถามรหัสผ่าน ให้สร้าง `dashboard/.env.local` แล้วใส่ `DASHBOARD_PASSWORD=...`

## รันค้างไว้ตลอดและเปิดเองหลังรีสตาร์ต

1. ปิด bot และ dashboard ที่รันอยู่ใน Terminal (Ctrl+C ทั้งสองหน้าต่าง)
2. เริ่มด้วย pm2 แล้วบันทึกรายการไว้
   ```bash
   npm install -g pm2
   cd ~/Desktop/Private/slip-tracker
   pm2 start ecosystem.config.cjs
   pm2 save
   ```
3. ตั้งให้เปิดเองตอนเข้าเครื่อง
   ```bash
   pm2 startup
   ```
   คำสั่งนี้จะพิมพ์คำสั่งอีกบรรทัดที่ขึ้นต้นด้วย `sudo env PATH=...` ให้คัดลอกบรรทัดนั้นมารัน แล้วใส่รหัสผ่านเครื่อง

หลังเปิดเครื่อง bot จะรอ Postgres และ SSD ให้พร้อมเองนานสุด 10 นาที จึงไม่ต้องเปิดตามลำดับ
ฐานข้อมูลอยู่บน SSD ภายนอก จึงต้องเสียบ SSD ไว้ และต้อง login เข้าเครื่องก่อนระบบจึงเริ่มทำงาน
ถ้าอยากเก็บรูปสลิปไว้บน SSD ด้วย ให้ตั้ง `SLIP_IMAGE_DIR` ใน `bot/.env` เป็น path บน SSD

คำสั่งที่ใช้บ่อย

| ต้องการ | คำสั่ง |
|---|---|
| ดูว่าทำงานอยู่ไหม | `pm2 status` |
| ดู log ของ bot | `pm2 logs slip-bot` |
| รีสตาร์ต bot (หลังแก้ `.env` หรืออัปเดตโค้ด bot) | `pm2 restart slip-bot` |
| อัปเดตหน้าเว็บ | `cd dashboard && npm run build && pm2 restart slip-dashboard` |
| หยุดทั้งหมด | `pm2 stop all` |

## สรุปจาก bot

bot ส่งสรุปให้เองทาง Telegram ตามเวลาไทย ตั้งค่าได้ใน `bot/.env`

| ค่า | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `DAILY_SUMMARY_TIME` | `20:00` | เวลาส่งสรุปประจำวัน ใส่ `off` เพื่อปิด |
| `WEEKLY_SUMMARY_DAY` | `sun` | วันที่ส่งสรุปประจำสัปดาห์ (`sun` ถึง `sat`) |
| `WEEKLY_SUMMARY_TIME` | `20:00` | เวลาส่งสรุปประจำสัปดาห์ ใส่ `off` เพื่อปิด |

- สรุปนับจากสลิปที่ส่งเข้าระบบในวันนั้นหรือ 7 วันล่าสุด และแนบสถานะเทียบเกณฑ์ของทุกธนาคาร
- ถ้า bot ดับตอนถึงเวลา จะส่งตามหลังเมื่อกลับมาทำงานภายในวันเดียวกัน และไม่ส่งซ้ำ
- ขอดูเองได้ทุกเมื่อด้วย `/today` และ `/week`

## การใช้งาน

- ส่งรูปสลิปเข้า bot ได้ทั้งแบบรูปและแบบไฟล์ bot จะตอบยอด ธนาคารที่รับเงิน และสรุปของธนาคารนั้นในปีนี้
- หลังบันทึกสลิป bot จะถามว่าลูกค้าซื้ออะไร (พิมพ์ตอบ) แล้วถามว่าจัดส่งหรือนัดรับ (กดปุ่ม) ถ้าพิมพ์ชื่อสินค้าเป็นคำบรรยายใต้รูปตอนส่งสลิป จะข้ามคำถามแรก
- ใต้ข้อความตอบกลับมีปุ่ม แก้ยอดเงิน / เปลี่ยนธนาคาร / ลบ / แก้สินค้า / แก้การรับของ
- ถ้าระบุธนาคารที่รับเงินหรือยอดเงินไม่ได้ bot จะถาม และยังไม่นับสลิปนั้นจนกว่าจะตอบ
- สลิปซ้ำ (เลขอ้างอิงเดิม) จะไม่ถูกนับเพิ่ม
- วันที่โอนมีที่มา 4 แบบ และกรองได้ในหน้ารายการสลิป: อ่านจากสลิป / อ่านไม่ได้ ใช้วันที่ส่งสลิป / อ่านเดือนไม่ชัด ประมาณเดือน / แก้ไขเอง
- หน้ารายการสลิปมีคอลัมน์จัดการ สำหรับแก้ไขและลบสลิป (ลบแล้วยอดของสลิปนั้นจะไม่ถูกนับ)
- มีเงินเข้าก่อนเริ่มใช้ระบบ: ส่ง `/settotal <ธนาคาร> <จำนวนครั้ง> <ยอดรวม>` โดยใส่ยอดรวมของปีนี้จนถึงตอนนี้ (รวมสลิปที่อยู่ในระบบแล้ว) ระบบจะเก็บส่วนต่างเป็นยอดยกมา และนำไปรวมตอนเทียบเกณฑ์
- คำสั่ง: `/today` `/week` `/settotal` `/summary` `/accounts` `/addaccount` `/delaccount` `/last` `/id` `/help`

## ขึ้นปีใหม่

ไม่ต้อง reset ระบบนับแยกตามปีปฏิทิน (เวลาไทย) จากวันที่โอนของแต่ละสลิป

- หลัง 31 ธ.ค. หน้าภาพรวม หน้ารายการสลิป และ `/summary` จะแสดงปีใหม่และเริ่มนับจาก 0 เอง
- ข้อมูลปีก่อนยังอยู่ครบ เลือกปีได้ที่มุมการ์ดยอดรับโอนในหน้าภาพรวม ที่ตัวกรอง "ปี" ในหน้ารายการสลิป หรือส่ง `/summary 2569`
- ยอดยกมา (`/settotal`) ผูกกับปีที่ตั้ง ไม่ถูกยกไปปีถัดไป
- สลิปที่โอนปลายปีแต่ส่งหลังปีใหม่ จะนับเข้าปีที่โอนถ้าอ่านวันที่จากสลิปได้ ถ้าอ่านไม่ได้จะใช้วันที่ส่ง จึงตกไปอยู่ปีใหม่ ให้แก้วันที่ในหน้ารายละเอียดสลิป

## วิธีอ่านสลิป

| ข้อมูล | อ่านจาก | ความน่าเชื่อถือ |
|---|---|---|
| เลขอ้างอิงรายการ, ธนาคารผู้โอน | QR บนสลิป | ตรงตัว |
| ยอดเงิน, วันเวลา | OCR | สูง แต่ควรดูตัวเลขในข้อความตอบกลับทุกครั้ง |
| ธนาคารที่รับเงิน | เทียบเลขบัญชี/พร้อมเพย์กับบัญชีที่ตั้งไว้ ถ้าไม่ตรงจะดูชื่อธนาคารในสลิป ถ้าไม่แน่ใจจะถาม | ขึ้นกับการตั้งบัญชีในข้อ 4 |
| ชื่อผู้โอน | OCR | อาจสะกดเพี้ยน แก้ได้ใน dashboard |

OCR ยืนยันไม่ได้ว่าสลิปเป็นของจริง ระบบนี้ใช้บันทึกยอด ไม่ได้ใช้ตรวจสลิปปลอม

## เกณฑ์ที่ใช้เทียบ

นับต่อปีปฏิทิน ต่อธนาคาร รวมทุกบัญชีในธนาคารเดียวกัน (แก้ได้ที่ `bot/src/thresholds.js`)

- เงินเข้า 3,000 ครั้งขึ้นไป หรือ
- เงินเข้า 400 ครั้งขึ้นไป และยอดรวม 2,000,000 บาทขึ้นไป

ระบบนับเฉพาะสลิปที่ส่งเข้ามา ธนาคารนับเงินเข้าทุกรายการ ตัวเลขจริงจึงอาจสูงกว่าที่เห็นใน dashboard
bot จะเตือนเมื่อถึง 80% ของเกณฑ์

## ทดสอบ

```bash
cd bot
TEST_DATABASE_URL=postgres://localhost:5432/slip_tracker_test npm test
```

ต้องสร้างฐานข้อมูลทดสอบก่อน (`createdb slip_tracker_test`) ชุดทดสอบจะลบและสร้างตารางในฐานข้อมูลนั้นใหม่ทุกครั้ง
รูปใน `bot/test/fixtures` เป็นสลิปจำลอง ไม่ใช่สลิปจริง
